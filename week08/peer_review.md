## 一、能不能跑
- **现象描述**：我通过浏览其 Gitee 仓库，确认核心文件（`assistant_v1.py`、`README.md`、`requirements.txt`、`answer_log.md`）均齐全。虽然本次互评未实际下载并运行代码，但基于其详实的 README 说明和完整的依赖清单，推断该代码具备可运行的基础。
- **三问是否都有回答**：根据其 `answer_log.md` 及 README 中的“跑完整对照实验”说明，程序默认会执行“三问三答”并输出结果。

## 二、README 能复现吗
- **现象描述**：能复现。她的 README 结构非常清晰：
  1. **怎么装**：明确列出了 `pip install -r requirements.txt`、拉取两个 Ollama 模型，以及配置 `.env` 密钥的步骤。
  2. **怎么用**：不仅提供了基础的 `python assistant_v1.py` 运行命令，还详细说明了如何通过参数（如 `--prefer api`、`--no-rag`、`--ask`）切换不同模式，甚至附带了运行对照实验的脚本 `run_demo.py`。
- **卡在哪一步**：未实际卡壳（因未进行本地下载运行），但说明文档详实，无缺失步骤。

## 三、Release 发了吗
- **现象描述**：已发布。远端仓库有明确的 `v1.0` 标签，且 Release 页面附带了功能、安装和用法说明，非常规范。

## 四、有没有已知限制
- **现象描述**：有，且非常诚实。她在 README 的“已知问题”中详细列出了 4 点：
  1. 未启动 Ollama 时报错提示及解决方式（切云端或开启 serve）。
  2. 承认本地小模型在 RAG 下会读错表格（如 HSK4 词汇答成 300），并给出默认用云端的建议。
  3. 说明了知识库目前只有三份资料，部分问题会如实回答“未提及”。
  4. 提示了检索 k=5 是当前语料库调优的结果，换语料需重建 `chroma_db_w8/`。
