# 开源项目拆解反思
1. **我的 `rag_qa.py` 与官方 2-Step RAG 差在哪一步？**
我的代码完全实现了官方的 2-Step RAG 流程（检索->生成）。唯一的区别在于“组件选择”与“工程化程度”。官方使用 LangChain 的链式调用（Chain）和云端 Embedding，而我为了隐私和离线可用，使用了本地的 `nomic-embed-text` 和 Ollama 双引擎兜底，结构更轻量，但缺乏官方的多组件无缝替换能力和 Streamlit 的可视化界面。
2. **如果要从 2-Step 走到 Agentic RAG，需要补上什么能力？**
Agentic RAG 需要模型自己决定何时检索、如何检索。我需要补上 **W9 的工具调用（Function Calling）能力**，让 LLM 能自主调用 `retrieve()` 函数作为它的一个外部工具，并根据检索结果决定是否继续检索或直接生成。
3. **llm-universe 没有 LICENSE，为什么只能参考思路？这与 .env 的红线有什么共同点？**
没有 LICENSE 默认适用“保留所有权利”，我们不能直接复制代码进仓库。这与 `.env` 密钥不能入仓的红线一样，**核心都是“数字公民的合规与安全底线”**。复制无许可代码等于学术不端/侵权，泄露密钥等于财产损失；两者都要求我们做到：**只参考逻辑与架构，坚决不直接把敏感/受保护的资产据为己有。**
